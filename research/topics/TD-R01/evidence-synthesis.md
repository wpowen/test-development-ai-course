# TD-R01 Evidence Synthesis

## Fact

The source document contains a broad route from traditional testing through Python, ML/DL/LLM, Prompt, architecture, RAG/Agent, evaluation, tools, workflows, projects, and a glossary/FAQ. Official documentation, professional syllabi, standards, repositories, and research are appropriate anchors for a maintained index. They do not prove that a link is currently accessible, that a version fits a learner, or that reading it creates job readiness.

## Cross-source synthesis

Route A organizes resources by learning objective and evidence authority. Route B tests staleness: a link has no checked date, a tool version is incompatible, a resource has no purpose, or a blocked source has no fallback. Agreement: every record needs version, checked_at, purpose, limits, fallback, and exit artifact. Adjudication: a learner selects by background and gap, then produces a small artifact such as a pytest run or Metric Card; a stale resource becomes BLOCKED rather than silently recommended.

The method is: capability gap → learner background → resource record → version and checked date → applicability → fallback → exit artifact → review update. Prompt output is an index candidate only. The runner mutates checked date, fallback, and exit artifact fields so an unmaintained list becomes red.

## Inference

A maintained index is more reusable than a static book list because it tells a beginner why to use a resource, what it cannot prove, and what to do if it drifts. Exit artifacts also turn passive consumption into an observable learning step; they do not prove long-term retention.

## Unknown

Current URL accessibility, version compatibility, instructional quality, learner time, learning effect, employer relevance, and employment outcome remain unknown. Any “best” or “must learn” label requires a separate dated review.
