# TD-R01 Research Brief

## Controlling question

How can a learner turn a broad book, platform, framework, prompt, architecture, evaluation, and workflow list into a maintained route with version, checked date, purpose, limits, fallback, and an exit artifact? The source document is rich but links and tool versions can drift. The course therefore teaches a resource index, not an unqualified “best books” list.

The scope includes zero-background, tester-background, and developer-background entry paths; AI foundations; prompt design; architecture; evaluation; RAG/Agent; automation; and an executable artifact for each stage. It excludes claims that a resource is current, accessible, effective, or employment-producing until independently checked.

## Evidence / Inference / Unknown

Evidence: official documentation, professional syllabi, standards, repositories, and research can anchor learning routes. Inference: fallback and exit artifacts prevent a stale resource from blocking progress. Unknown: current URL availability, version compatibility, instructional quality, and individual learning effect.

## Learner decision

The learner must choose an entry path, record a checked resource, name its limits and fallback, and run TD-R01 baseline/fault/repair. Missing freshness or exit artifact is `BLOCKED`.
