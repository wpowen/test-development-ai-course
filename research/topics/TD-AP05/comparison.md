# TD-AP05 两轮研究比较

## Agreements

两轮研究都要求把饱和点、队列和瓶颈归因绑定到受控实验。

## Run A：官方规格与实现

优势：给出 容量曲线与瓶颈归因 的字段、公式、调度或工具接口，可直接形成 schema 和 typed technical block。限制：产品/标准文档证明语义与功能存在，不证明目标环境效果。

## Run B：失败、运维与学习供给

优势：暴露队列、重试、Trace 缺口、资源增长和告警误用等反例，并能形成 fault mutation 与 Runbook。限制：issue 是具体环境报告，不能普遍化。

## Disagreements

不同平台对瓶颈指标的实现与命名并不一致。

## Adjudication

课程锁定本地字段与阈值，禁止把 synthetic 曲线推广为生产容量。

裁决后的作业必须提交第一失效点、控制变量和下一步真实容量实验计划，不能只交一条最大并发数字。

## 独立比较结论

最终判断必须附阶梯表、第一失效级别、受控变量与独立重算；synthetic 曲线不构成容量承诺。任何阈值变化都必须有 owner 和决策记录，并保留原始曲线与失败样本供复核；没有归因就不能放行。报告必须同时列出不确定性与后续真实环境验证计划。

学习者必须把两轮证据转换成阶梯实验表、第一失效点、控制变量、归因和独立 Oracle 重算，而不是提交最大并发数字。

两轮证据一致支持“版本化负载 + 可下钻证据 + fail-closed gate”。差异在于 Run A 偏定义，Run B 偏失效机制。课程同时保留二者：定义决定字段，失效机制决定 mutation。Production capacity、组织阈值和 practitioner sign-off 保持 Unknown。任何外推都必须重新建立证据。
