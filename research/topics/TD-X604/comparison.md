# TD-X604 双研究 Run 比较

比较采用相同决策问题、不同来源集合和不同审查角色。R1 不读取 R2 的裁决，R2 不把 R1 的结构完整当作效果证据；最终 reviewer 只合并双方都能回到打开来源、工程工件和明确限制的主张。这个分离用于减少确认偏差，但不声称消除了研究者偏差。

## Agreements

R1 从标准、官方文档和职业框架提取输入身份、版本、指标、审计与责任边界，把 模型路由、Provider Fallback 与工具协议漂移 拆成可检查工件，支持 请求合同 → 能力/区域/权限匹配 → provider 路由 → 协议与 Schema 校验 → fallback 重新授权 → 副作用门禁 → Trace 与回滚。局限是这些文档通常描述规范或产品能力，不提供本课程、当前组织或真实用户的效果数据。

## Disagreements

R2 专找假绿：平均值遮蔽最坏切片、同模型自评、样本只选成功、工具覆盖不全、版本和协议漂移、无效 HITL、缓存陈旧、回滚不可用以及静态结果被误写成安全。故障为 把请求降级到不满足能力的 fallback，并注入工具 Schema 漂移。R2 要求保留原始工件、UNKNOWN、分歧和非零退出，避免把解释性文本当运行收据。

## Adjudication

共同支持候选与批准分离、输入版本化、独立 Oracle、逐切片指标、故障注入、具名 owner 和 fail-closed；不支持某工具通过即代表生产质量。fallback 必须重新检查权限、能力和 Oracle；缺版本或证据时拒绝执行，尤其不能重复副作用。。课程保留张力：确定性部分自动执行，语义、伤害、例外和发布由独立 owner 决定。自动化可报告 UNKNOWN，不能替 owner 合理补全。

采用版本合同、八类 eval、单点 mutation、baseline/fault/repair、报告哈希和限制；拒绝单一总分、生成器自批、无来源阈值和 fixture 外推。真实容量、价格、区域合规、模型等价性和协议升级时序。后续需要真实模型集成、从业者评审、样本代表性验证以及相关隐私、安全、无障碍或公平审查。
