# TD-P07 independent comparison

## Agreements

路线 A 与 B 同意：Run Manifest and Attribution Pack 由版本化输入驱动；关键 claim 有来源；冲突、未知和权限不能由 AI 决定；结果需要 receipt；离线 fixture 不能冒充生产证据。两者都反对用页面数量、JSON 合法、一次 exit 0 或模型自评替代专业完成。职业来源强调 test basis、traceability、风险与责任；实践来源强调 Schema、eval、contract、mutation 与收据；共同交集是可审计判断加可执行负控制。

## Disagreements

路线 A 对组织 authority、变更审批和术语更严格，但不指定本课程 Prompt 文件或 0/1/0 命令。路线 B 能给结构化输出、断言和 mutation 工具，却可能把工具配置当业务真相。AI 文档说明如何约束格式与评测，不证明业务规则正确；mutation 说明检测力，不证明风险选择完整。

证据粒度也不同：职业标准容纳人工评审，工程流水线需要机器可读 hash 与状态。课程同时保留可读 manuscript/decision 和机器可验 manifest/report，不让任何一边吞掉另一边。

## Adjudication

独立 reviewer 裁决：运行前钉住所有 hash；证据不足保持 BLOCKED 或 UNKNOWN，不得 PASS。 authority 与业务 Oracle 由具名专业 owner 控制；Prompt、Schema、eval、mutation 和 pipeline 执行已批准判断。UNATTRIBUTABLE_RUN 必须在 fault 阶段稳定变红，repair 只修根因。当前结论限于 fixture-tested；live model、企业集成、从业者认可、发布与生产均为 Unknown/NOT_RUN。
