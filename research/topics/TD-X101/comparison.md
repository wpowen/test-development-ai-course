# TD-X101 双研究 Run 比较

比较采用相同决策问题、不同来源集合和不同审查角色。R1 不读取 R2 的裁决，R2 不把 R1 的结构完整当作效果证据；最终 reviewer 只合并双方都能回到打开来源、工程工件和明确限制的主张。这个分离用于减少确认偏差，但不声称消除了研究者偏差。

## Agreements

R1 从标准、官方文档和职业框架提取输入身份、版本、指标、审计与责任边界，把 静态、架构、代码与依赖供应链质量 拆成可检查工件，支持 信任边界 → commit/diff → SBOM → provenance/signature → 扫描发现 → owner/例外 → 合并门禁。局限是这些文档通常描述规范或产品能力，不提供本课程、当前组织或真实用户的效果数据。

## Disagreements

R2 专找假绿：平均值遮蔽最坏切片、同模型自评、样本只选成功、工具覆盖不全、版本和协议漂移、无效 HITL、缓存陈旧、回滚不可用以及静态结果被误写成安全。故障为 加入未签名依赖并删除 critical finding owner。R2 要求保留原始工件、UNKNOWN、分歧和非零退出，避免把解释性文本当运行收据。

## Adjudication

共同支持候选与批准分离、输入版本化、独立 Oracle、逐切片指标、故障注入、具名 owner 和 fail-closed；不支持某工具通过即代表生产质量。未签名、无 provenance 或无人负责的 critical 发现必须阻断；没有发现不等于系统安全。。课程保留张力：确定性部分自动执行，语义、伤害、例外和发布由独立 owner 决定。自动化可报告 UNKNOWN，不能替 owner 合理补全。

采用版本合同、八类 eval、单点 mutation、baseline/fault/repair、报告哈希和限制；拒绝单一总分、生成器自批、无来源阈值和 fixture 外推。真实构建环境、私有依赖、语言覆盖、误报率与组织例外政策。后续需要真实模型集成、从业者评审、样本代表性验证以及相关隐私、安全、无障碍或公平审查。
