# TD-F01 Independent Comparison

## Agreements

Route A 与 Route B 都认为测试开发不能被压缩为执行或自动化。A 从职业框架、专业大纲和需求/系统工程得到早期工件分析、风险方法、可追溯依据、验证矩阵、执行诊断和发布准备；B 从 API/Schema、AI 风险治理、安全和反例得到版本、结构门禁、全生命周期 TEVV、人类监督和权限边界。两条路线都要求工件进入真实下游决定，都拒绝把模型输出或被测实现作为天然 Oracle，都要求目标公司内部规则保持未知。

两条路线也同意职业入口需要完整研发测试链。需求与技术设计分别读取；权威冲突阻断；风险决定方法；Oracle 独立；环境、数据和构建受控；执行结果可归因；发布由具名 owner 决定；生产反馈进入回归资产。AI 质量是这条链的扩展，而不是用 Prompt 替换专业基础。

## Disagreements

Route A 更强调稳定的职业共同结构和成熟度层级，容易让课程看起来像传统测试大纲；Route B 更强调 AI 系统的新对象、权限与安全，容易让新人过早进入 Dataset、Judge、Agent 等术语。裁决是先用一个订单取消场景讲明传统链，再用映射表展示 AI 迁移，不让 AI 内容遮蔽需求、风险和发布责任。

Route A 的政府/专业框架可能让人误以为存在统一职级；Route B 的 GitLab 迁移和 Reddit 讨论显示职位名、年限和组织结构高度变化。裁决是保留“责任范围、复用杠杆、跨团队影响”的成长方向，删除任何按年限保证职位的表达，并把 GitLab/论坛严格标为 counterevidence/practitioner-signal。

Route B 倾向用 Schema 与自动化 Gate 强化可执行性，但 Schema 只能证明结构，不能证明业务语义。Route A 的权威与验证矩阵补足语义来源。裁决是 Prompt 同时绑定 Schema/Eval/Mutation，且关键业务冲突与高风险发布保持人类裁决；provider none 不得写成模型 PASS。

## Adjudication

最终页面保留原有职业节奏、依赖、工件、晋升证据、痛点分类、资深 Agent 提示词和个人岗位练习，不做删减。新增五个必要层：一句话职业责任、九阶段研发测试全链、需求/技术双文档读法、传统到 AI 的能力迁移、可运行入场自测与门禁学习路线。

技术呈现全部 typed：生命周期为不可运行 diagram；职业责任地图为 config；Prompt 绑定版本、输入、Schema 和 Eval；唯一 command 精确绑定公开 manifest 的 cycle step。Canonical/public/ZIP 必须闭包。状态上限为 fixture-tested，因为确定性 0/1/0 已运行；模型、从业者、企业集成、线上、发布和生产均未运行。

独立比较结论为 ACCEPT-WITH-FIXTURE-BOUNDARY。若任何后续修改减少责任/工件地图、把技术设计当权威真值、把 AI 设为发布人、删除 fault=1 证据、或把 provider none 写成模型通过，应视为回归并阻断。
