## 9.2 能力矩阵 L1–L5

**说明**：这是**能力**分级，不是职级。职级、年限、晋升周期由组织决定，本手册不作规定——需要时填入 `templates/12-raci-and-level-adapter.md` 的组织适配器部分，缺 owner 时保持 `INTERNAL-UNKNOWN`。

| 能力域 | L1 跟做 | L2 独立执行 | L3 设计 | L4 系统 | L5 治理 |
| --- | --- | --- | --- | --- | --- |
| **测试依据** | 能按模板登记来源 | 能独立冻结一个需求批次 | 能设计来源优先级规则 | 能建立组织级 Basis 规范 | 能裁决跨部门依据冲突机制 |

| **风险与策略** | 能按矩阵打分 | 能独立出风险登记册 | 能制定项目测试策略 | 能建组织风险模型 | 能设定风险容忍度 |
| **Oracle** | 能使用现成 Oracle | 能为常规条件设计 Oracle | 能设计变形关系与复合 Oracle | 能建 Oracle 库与校准流程 | 能裁决 Oracle 争议 |

| **归因** | 能提交缺陷 | 能定位到层 | 能设计可观测性需求 | 能建归因体系 | 能推动跨团队根因治理 |

## 9.5 估算与排期

### 不要用的估算方式

- 按"用例条数 × 单条工时"——用例条数是结果不是输入；
- 按"上次也差不多这么久"——上次的风险构成可能完全不同；
- 按开发工时的固定百分比——与风险无关。

### 推荐：按风险档位估算

```text
测试投入 = Σ (各档位风险数 × 该档位单位投入)
```

| 档位 | 单位投入构成（示例结构，非数值建议） |
| --- | --- |
| 关键 | 契约化 + 独立 Oracle 设计 + 用例 + 变异 + 故障注入 + 人工复核 + 监控项 |
| 高 | 契约化 + Oracle + 用例 + 负例集 |
| 中 | 用例 + 边界 |
| 低 | 冒烟 |

**首次使用**：不要估算，先**实测**一个完整需求批次的各档位耗时，得到你团队的单位投入。第二个批次开始才用它估算。

### 必须单列的隐性成本（最常被漏）

```text
□ 环境搭建与维护
□ 测试数据准备与脱敏审批等待
□ 评测集标注（人工标注是主要成本项）
□ Judge 校准
□ Flaky 治理
□ 缺陷复现与归因（AI 场景下常常超过用例编写本身）
□ 生产事件回灌
□ 依赖方联调等待
```

### 排期原则

1. **S1–S5 与开发并行**，不是开发完再开始；
2. **变异与故障注入不能压缩**——它们是唯一证明检测力的手段；
3. **人工标注与复核要预留等待时间**，它不是可压缩的工程任务；
4. 排期中显式留出 **UNKNOWN 缓冲**（AI 项目的归因耗时方差极大）。
