# 06 阶段方法：S9 发布判断与生产闭环

---

## 9.1 准出准则：什么叫"可以发了"

**准出不是"用例都跑完了"，而是"约定深度的风险已被覆盖，剩余风险已被具名接受"。**

### 通用准出模板（按档位）

| 检查项 | 关键风险 | 高风险 | 中风险 | 低风险 |
| --- | --- | --- | --- | --- |
| 需求契约无 `BLOCKED` | 必须 | 必须 | 必须 | 必须 |
| 独立 Oracle 已就位 | 必须 | 必须 | — | — |
| 变异杀死率达标 | 必须 | 必须 | — | — |
| 故障注入 0/1/0 通过 | 必须 | 必须 | 建议 | — |
| blocker 切片全绿 | 必须 | 必须 | 必须 | — |
| 重复运行分布在区间内 | 必须 | 必须 | 建议 | — |
| 安全攻击集无泄露/无写入 | 必须 | 必须 | 建议 | — |
| 人工抽检完成 | 必须 | 抽样 | — | — |
| 回滚预案已演练 | 必须 | 必须 | 建议 | — |
| 生产监控项已上线 | 必须 | 必须 | — | — |
| 成本/延迟未劣化超阈值 | 必须 | 必须 | 建议 | — |

⚠ 表中"达标""阈值"一律为占位。首次使用时由发布 owner 与测试负责人共同设定并写入《测试策略》。

### 发布前必须能回答的七个问题

如果任何一个答不上来，就还不能发：

1. 这个版本相对上一个版本，**只改变了什么**？
2. 已知**坏版本**能否被当前门禁稳定拦下？（证据在哪）
3. 高风险切片上，**失败率的区间**是多少？（不是平均分）
4. 出问题时，**多久能发现**、**多久能回滚**？
5. 哪些风险**明知没测**？谁签字接受？
6. 这次变更的**成本与延迟**变化是多少？
7. 生产上用**哪个信号**判断"确实没问题"？

## 9.2 Waiver（豁免）流程

Waiver 是合法的工程手段，前提是**它必须过期**。

```text
Waiver ID      : W-2026-0812-01
关联门禁       : Gate-3 / 变异杀死率
未满足内容     : 退款路径杀死率 62%（约定 ≥80%）
业务原因       : 修复窗口不足，本次仅上线只读功能
补偿控制       : 退款入口对新版本关闭；生产告警阈值收紧至 <原值>
影响范围       : 仅 refund 模块只读路径
批准人         : <姓名/角色>            批准日期：<日期>
过期时间       : <日期，最长 2 个迭代>   ← 必填，不允许"长期"
过期后动作     : 自动恢复门禁并阻断发布
回滚条件       : 出现任一 S1/S2 退款缺陷即回滚
```

**四条禁令**：

1. 没有过期时间的 Waiver 无效；
2. 没有补偿控制的 Waiver 无效；
3. Waiver **不能由测试开发单方签**，必须由发布 owner 签；
4. 同一门禁连续 3 次被 Waiver → 门禁本身必须重新评审（要么阈值不合理，要么工程债需立项）。

## 9.3 发布决定书

发布不是流水线绿灯，是一份**署名决定**。

```text
版本            : v3.4.0 / <git sha>
变更摘要        : <一句话>
证据链接        : run_id 列表、报告路径
门禁结果        : Gate-1 PASS / Gate-2 PASS / Gate-3 PASS（1 项 Waiver W-…）
剩余风险        : R-014 跨租户路径未验证（HIGH，接受人 <姓名>）
                  R-021 长上下文降级未测（MED，接受人 <姓名>）
发布方式        : 影子 3 天 → 金丝雀 5% × 2 天 → 全量
回滚触发条件    : ① S1/S2 缺陷 ② 退款切片失败率 > <阈值> ③ p95 > <阈值>
回滚执行人      : <姓名/角色>          预计回滚耗时：<分钟>
生产观察项      : <指标 1..N> 与告警阈值
决定人          : <发布 owner 姓名>    日期：<日期>
成熟度声明      : 本次证据等级 L<n>；未覆盖 L<n+1..5>
```

## 9.4 渐进发布策略（AI 变更强烈建议）

| 阶段 | 流量 | 观察什么 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 影子 | 0%（并行跑，不返回给用户） | 输出差异分布、成本、延迟 | 差异集中在预期范围；无 blocker 类差异 |
| 金丝雀 | 1–5% | blocker 切片、投诉、人工抽检 | 观察窗内无 S1/S2；分布未劣化 |
| 放量 | 25% → 50% | 同上 + 容量指标 | 同上 |
| 全量 | 100% | 持续评估基线 | — |

**AI 特有提醒**：影子阶段的"输出不一致"**不等于**错误。必须先用 Oracle 判定差异性质，再决定是否阻断——否则每次模型升级都会因为措辞变化被全部拦下。

## 9.5 生产闭环

### 9.5.1 持续评估（Continuous Evaluation）

传统系统发布后行为稳定；AI 系统会漂移。因此**发布不是终点**。

| 频率 | 动作 | 产出 |
| --- | --- | --- |
| 每次请求 | 结构与规则层在线校验（低成本 Oracle） | 实时 blocker 告警 |
| 每小时 | 关键切片抽样 + 自动打分 | 漂移曲线 |
| 每日 | 固定金标集回放 | 与发布基线对比 |
| 每周 | 人工抽检 N 条（含高风险切片） | 人工一致性记录 |
| 每月 | 全量评测集重跑 + 数据分布对比 | 漂移报告与重训/回滚建议 |

**漂移判定**：连续 <N> 个观察窗，关键切片指标偏离发布基线超过 <区间>，触发调查。区间由重复运行的历史分布确定，**不是拍脑袋定一个百分比**。

### 9.5.2 Trace-to-Regression（逃逸缺陷回灌）

每一个生产逃逸缺陷都必须走完这条链，**5 个工作日内闭环**：

```text
生产事件
  → 捕获完整 Trace / 输入 / 版本 / 用户影响面
  → 脱敏
  → 在测试环境稳定复现（记录复现率 M/N）
  → 定位到五层归因中的哪一层
  → 补一条能稳定变红的回归用例（并入对应 Gate）
  → 用变异验证这条用例确实有检测力
  → 反查：同类风险还有哪些未覆盖 → 补进风险登记册
  → 更新 Oracle / 数据集 / 攻击集
  → 记录到缺陷逃逸台账
```

**不允许**的做法：只修代码不补用例；只补用例不验证检测力；只处理这一个 case 不做同类反查。

### 9.5.3 缺陷逃逸台账

按月统计，用于回答"我们的门禁到底有没有用"：

| 字段 | 说明 |
| --- | --- |
| 逃逸缺陷数 | 按 Severity 分 |
| 逃逸原因分类 | 未覆盖风险 / Oracle 不足 / 数据不代表 / 环境差异 / 已知但被 Waiver |
| 应被哪一层拦下 | Gate-1..4 |
| 补救动作 | 用例 / Oracle / 数据 / 门禁调整 |
| 同类反查覆盖数 | 反查补了多少条 |

⚠ 若"已知但被 Waiver"占比升高，说明问题不在测试能力，在**发布纪律**。

### 9.5.4 回滚

回滚必须**演练过**才算存在。AI 系统的回滚有一个特殊陷阱：

> 回滚模型别名不等于回滚系统。Prompt、检索索引、工具版本、Scorer 阈值必须**成组回滚**，否则会退到一个从未被测试过的组合。

**回滚预案必填**：回滚对象清单（五要素）、执行人、预计耗时、验证方式、回滚后数据一致性处理。

## 9.6 准出检查（S9）

- [ ] 准出准则按风险档位逐项判定，未通过项已走 Waiver
- [ ] 所有 Waiver 有过期时间与补偿控制
- [ ] 发布决定书由发布 owner 署名，剩余风险已具名接受
- [ ] 回滚预案已演练，回滚对象为五要素成组
- [ ] 生产观察项与告警阈值已上线
- [ ] 持续评估节奏已配置
- [ ] 上一周期的逃逸缺陷已全部完成 Trace-to-Regression
