# Prompt 包设计契约

版本 v1.0 ｜ 适用：本项目全部 `prompt-v1.md` 与 `critic-v1.md`

> 这份契约回答一个问题：**一份提示词写到什么程度才算写完了。**

## 1. 为什么需要它

改造前实测 50 份提示词：

| 诊断维度 | 实测 |
| --- | --- |
| 结构化程度 | 42/50 是单段落，8/50 有任何分节 |
| 示例质量 | **0/50** 有示例 |
| 输出规范 | **0/50** 在提示词内声明输出规范 |
| 约束明确性 | **0/50** 有独立约束段，全挤在同一段 |
| 推理策略 | **0/50** 有推理路径引导 |
| 自检机制 | **0/50** 有自检清单 |
| 中位长度 | 约 620 字节 |

典型样本（TD-X101，改造前全文）：

> Role: evidence-bounded quality candidate generator. Task: 把架构边界、静态发现、SBOM、签名与例外 owner 连接成合并门禁. Read only the fixed input. Return JSON matching schema. …

它不是错的，它是**不可执行**的：模型不知道按什么顺序思考、不知道输出长什么样、不知道边界情况怎么处理，也没有任何自检依据。

## 2. 七段结构

每份任务提示词必须包含以下七段，缺一即不通过门禁：

| 段 | 回答什么 | 主要来源 |
| --- | --- | --- |
| 1 角色与专业定位 | 你是谁、你的判断力来自哪里 | spec.role / spec.expertise |
| 2 任务目标与成功标准 | 做完什么算做完 | spec.objective + schema.required |
| 3 上下文与输入边界 | 能用什么、什么算不可信注入 | input.json 字段 + spec.untrusted |
| 4 推理策略与思考路径 | 按什么顺序想 | spec.steps（对齐 eval 的用例类型） |
| 5 示例与模式学习 | 正例、边界例、拒答例各一 | spec.examples |
| 6 约束与安全护栏 | 优先级 1 / 优先级 2 / 红线 | manifest.authority + stop_states |
| 7 输出规范与自检清单 | 输出形状 + 提交前逐条自查 | schema + spec.checklist |

## 3. 与包内其他文件的强制对齐

提示词不是独立文件，它是 Prompt 包的一部分。门禁校验以下交叉引用：

- **每个 `manifest.stop_states` 必须在提示词里被逐字提到。** 声明了停止状态却不告诉模型，等于没有停止状态。
- **每个 `schema.required` 字段必须在输出规范段里被逐字提到。** 否则模型不知道哪些字段不可省略。
- **拒答示例必须触发一个真实存在的 `stop_state`。** 编一个不存在的状态名，等于示例在教错误行为。

这三条与页面层的「架构图节点必须被正文引用」是同一个机制：让**声明**与**内容**之间的漂移变成构建错误，而不是文档瑕疵。

## 4. 示例的最低要求

- **正例**：一段真实输入片段 + 一份完整的 JSON 输出，字段齐全。
- **边界例**：证据不足、冲突或截断，说明为什么它仍然产出结论或为什么不产出。
- **拒答例**：必须命中 stop_state，输出里 `status` 不得是成功态。

三种缺任何一种都不通过。只给正例的提示词会让模型把「一定要给出答案」当成隐含目标。

## 5. 生成而非手写

提示词由 `scripts/build-prompt-packages.py` 从两处合成：

- `methodology/prompt-specs.json` —— 逐主题的设计数据（角色、目标、推理步骤、示例、约束）
- 包自身的 `manifest.json` / `schema.json` / `eval.json` / `mutation.json` / `input.json` —— 提供锚点

改提示词请改 spec 后重新生成。直接编辑 `prompt-v1.md` 会在下次重建时被覆盖。

理由与站点内容层相同：同一份提示词在 `learner-materials/`、`lab/`、`site/public/materials/` 与 ZIP 中共有四份字节一致的副本，手工同步必然漂移。

## 6. 证据边界

本契约规定的是**提示词的结构完整性**，不是它的效果。

所有 Prompt 包的 `model_evidence` 当前为 `NOT_RUN`：结构合规、示例完整、交叉引用一致，都不代表接上真实模型会得到期望输出。效果需要真实运行 + 评测才能声明，而那一级尚未执行。
