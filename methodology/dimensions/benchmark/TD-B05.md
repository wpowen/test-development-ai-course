## TD-B05

### 隐藏测试集能防止过拟合，但它防不住其他四种失真

把测试集藏起来是应对污染最直接的手段，也因此容易被当成充分手段。它解决的是「模型见过题」，解决不了样本量、版本可比性、重复暴露与不确定性这四个问题。



| 失效形态 | 可核查的数字 | 它导致的错误结论 |
| --- | --- | --- |
| 样本量不足就发布排名 | 样本 100 条时两个 85% 与 82% 的结果，其 95% CI 通常大幅重叠，不构成排名依据 | 榜单上的名次差被当成能力差，实际统计上无法区分 |
| 跨版本比较未检查兼容性 | 数据集或评分协议改版后新旧分数不可比；实测中改版带来的整体平移可达 3～8pt，方向不固定 | 看到分数下降就排查模型，实际是评测集改版了 |
| 隐藏集被反复访问 | 隐藏集的无偏性随访问次数下降，累计开封 ≥ 3 次即应整体重建；缺访问审计时无法知道它已被看过多少次 | 把一个已经事实上公开的集合当成隐藏集使用 |

> 本页的产物是一张可信度分类表：把每个分数标注为可比、有限可比、不可比三类之一。

### 污染与不确定性的四个词

这一页处理的是「分数是真的吗」，而不是「分数是多少」。

| 术语 | 一句话解释 |
| --- | --- |
| 训练污染 | 评测样本已进入训练数据；此时分数是记忆而非能力 |
| 近重复 | 与训练样本高度相似但不完全相同；它比精确重复更难检测 |
| 隐藏测试集 | 不公开样本以防污染；它降低风险但不能消除 |
| 跨版本可比 | 不同时间的两次评测能否比较；模型、数据、Harness 任一变化都会破坏它 |

> 更完整的中英对照见方法论 02 术语表；这里只收本页判断真正依赖的几个。

*依据：[SWE-bench/SWE-bench](https://www.swebench.com/)*

### 隐藏测试集挡得住过拟合，挡不住训练污染

隐藏测试集解决的是「反复在同一份数据上调优」这类过拟合。它解决不了污染：如果这些题目本来就在模型的预训练语料里出现过，隐藏与否都不影响模型已经见过它们这个事实。

污染有三种形态，检测手段与可检出程度完全不同：逐字重复（可用检索或哈希检出）、近重复（换个说法的同一道题，需要嵌入相似度加人工抽检）、间接泄漏（题目本身没出现，但解法与答案在语料里，几乎无法检出）。第三种是公开 benchmark 分数虚高的主要来源。

因此企业基准必须优先使用内部数据，并记录数据时间戳与模型训练截止日期的关系。时间边界是目前成本最低、也相对最可靠的一道污染防线——虽然它同样不完美，因为训练截止日期本身往往并不精确，且增量训练不会公告。

跨版本可比是最后一环：模型升级之后旧分数不再有效，因为新模型可能见过更多。正确做法是每次升级重建基线，而不是把新分数与历史分数直接连成一条上升曲线——那条曲线里混着能力提升和污染加深两件事。

*依据：[SWE-bench/SWE-bench](https://www.swebench.com/) · [EleutherAI/lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness#readme)*

### 三种污染形态的可检出程度差了两个量级

这张表要说明的是一件不太舒服的事：最严重的那种污染，恰恰是最检不出来的那种。

因此结论不是「检测干净了就可以信」，而是「公开基准的绝对分数一律按上界看待，选型必须落到自建基准上」。

| 污染形态 | 检测手段 | 可检出程度 | 残留风险 |
| --- | --- | --- | --- |
| 逐字重复 | 检索或哈希比对 | 高 | 语料不公开时根本无法比对，这是常态而非例外 |
| 近重复（换说法的同一题） | 嵌入相似度 + 人工抽检 | 中 | 阈值需人工定，误判在两个方向上都存在 |
| 间接泄漏（解法在语料里） | 几乎没有可行手段 | 低 | 公开 benchmark 分数虚高的主要来源 |
| 时间边界核对 | 数据时间戳 vs 训练截止日期 | 中，且成本最低 | 训练截止日期本身不精确，增量训练不公告 |

> 四行里没有一行能给出「已排除污染」的结论。能给出的最强陈述是「已排除逐字重复与近重复，间接泄漏未知」。

*依据：[SWE-bench/SWE-bench](https://www.swebench.com/) · [EleutherAI/lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness#readme) · [stanford-crfm/helm](https://crfm.stanford.edu/helm/)*

### 四类不确定性来源与各自的检测手段

一个分数的不确定性有四个来源，它们需要不同的检测手段，不能用一个置信区间概括。

右列是可以今天就做的检测——多数不需要额外算力。

| 不确定性来源 | 表现 | 检测手段 |
| --- | --- | --- |
| 采样随机 | 同输入不同结果 | 重复运行看分布 |
| 样本量不足 | 区间过宽 | 算区间而不是只报点估计 |
| 训练污染 | 公开集异常高分 | 用私有近似任务对照 |
| 近重复 | 改写后分数骤降 | 做语义近重复检索 |

> 第三与第四行常被合并处理，但它们的补救方式不同：污染要换数据，近重复要改抽样。

*依据：[SWE-bench/SWE-bench](https://www.swebench.com/)*

### 这一页的验收口径：先判断可信度，再看分数

本页的核心产物是 B05-4 的可信度分类。它比分数本身更有价值：一个被标为「不可比」的高分，不会被误用；一个被标为「可比」的低分，可以放心地作为基线。

B05-2 的金丝雀检测是一个低成本高收益的做法：埋入少量特征样本，一旦外泄立刻可知。

| 编号 | 测什么 | 关键指标 | 复测频率 |
| --- | --- | --- | --- |
| B05-1 | 样本充分性 | 结论所依据的样本 ≥ 100 条；不足时结论标记为「证据不足」而非给出排名 | 每次评测 |
| B05-2 | 泄露检测 | 金丝雀样本在外部出现的次数 = 0 | 每季度 1 次 |
| B05-3 | 版本兼容 | 跨版本比较前完成兼容性检查的比例 = 100%；不兼容仍比较的次数 = 0 | 每次比较 |
| B05-4 | 可信度标注 | 每个对外分数标注可信度分类的比例 = 100% | 每次报告 |

> 阈值一律是起点不是终点：带来源的按来源引用，其余是结构默认值，必须用你自己前三个版本的实测分布重标定后才能作为验收线。

### 两种看起来解决了污染、实际没有的做法

这两种做法都被广泛采用，也确实降低了风险。

问题在于它们被当成了完全的解决方案。

| 看起来合理的做法 | 为什么它看起来是对的 | 它实际上漏掉了什么 |
| --- | --- | --- |
| 使用不公开样本的隐藏测试集 | 样本没公开，模型没见过，逻辑成立 | 隐藏的是样本不是任务分布。相似任务的公开数据仍可能让模型学到解题模式。而且隐藏集无法被第三方复现，可信度依赖组织信誉 |
| 检查评测样本是否精确出现在训练语料中 | 精确匹配检测简单可靠，结果明确 | 近重复才是主要形式：换个变量名、改个措辞、调整数字。精确匹配几乎检测不到，需要语义相似度检索 |

> 两条的共同结论：污染只能降低概率，不能证明不存在。报告里应写「未发现污染」而不是「无污染」。

*依据：[EleutherAI/lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness#readme)*

### 怀疑分数虚高时按什么顺序查

虚高有四种成因，检测成本从低到高排列如下。先做便宜的。

四项都做过之后仍然虚高，才需要怀疑执行链路。

| 症状 | 先怀疑 | 下一步检查 |
| --- | --- | --- |
| 公开集远高于私有集 | 训练污染 | 用同难度私有任务对照 |
| 改写题面后分数骤降 | 近重复记忆 | 做语义改写鲁棒性测试 |
| 区间很宽但报了点估计 | 样本量不足 | 补样本或改写结论 |
| 跨版本对比差异大 | 可比性被破坏 | 核对模型、数据、Harness 三者版本 |

> 第二行的检测最便宜也最有效：把题面同义改写一遍重跑，分数骤降就是记忆而非能力。

### 做一次改写鲁棒性检测：约 45 分钟

这是性价比最高的污染检测手段，不需要访问训练数据。

1. 从评测集中抽取一批模型答对的样本。
2. 对每条做语义等价改写：换变量名、调整措辞、改变无关数字，保持答案不变。
3. 改写必须由人确认等价，不能用生成改写的同一模型自评。
4. 在改写集上重跑，比较分数。
5. 分数明显下降的部分单独列出——它们是记忆而非能力的候选证据。

**期望结果**：产出是一个改写前后的分数对比，以及一份可疑样本清单。下降幅度本身就是污染风险的量化代理。

> ⚠ 改写不能改变难度。把题目改简单或改难都会污染这次检测，改写只能动表述。

### 这一页的出口判据

这一页的门禁在报告发布前执行，它的作用是防止一个不可比的分数被当成可比的用。这类误用一旦发生，纠正的成本远高于事前标注。

第三段要接受的是污染的残余不确定性：无论审计多严格，都无法证明污染为 0，只能给出上界。

| 门禁段 | 判据 | 不满足时的处置 |
| --- | --- | --- |
| 第一段 · 硬红线（任一条不满足即阻断，无例外） | 金丝雀样本外部出现次数 > 0 时阻断，该封存集立即作废重建<br>未做兼容性检查的跨版本比较次数 > 0 时阻断 | 阻断发布，不进入后续两段 |
| 第二段 · 统计门禁（看置信区间，不看点估计） | 所有对外分数附 95% CI；样本 < 100 条时只报区间不报排名<br>污染率给出上界估计而非点估计，下界不得声称为 0 | 样本量不足时结论为「证据不足」，不是「通过」 |
| 第三段 · 风险接受（不是通过/失败，是具名决策） | 污染残余不确定性的上界，由评测 owner 签字接受<br>重建基线导致的历史不可比，由测试负责人明示接受 | 由具名 owner 签字接受剩余风险后放行 |

> 三段顺序执行：红线不过不看统计，统计不过不进风险接受。第三段永远需要人，不能由脚本代签。

### 带走一份不确定性声明

声明要写清四件事：重复了几次、区间多宽、做了哪些污染检测、结论的适用范围。

「未发现污染」和「无污染」是两句不同的话，报告里只能写前者。

- 改写鲁棒性检测优先做，成本最低
- 区间与样本量一起报，不只报点估计
- 写「未发现污染」而不是「无污染」

### 来源与延伸阅读

版本号、许可证与最近提交由 GitHub API 在构建时抓取，不是手抄的。
「不能证明」一列比「能证明」更重要：拿工具给结论背书，是本模块反复拆解的错误。

- **[lm-evaluation-harness：公开基准的标准执行器](https://github.com/EleutherAI/lm-evaluation-harness#readme)** — benchmark 执行器
  - 能证明：同一个 benchmark 在不同 harness 下会得到不同分数：prompt 模板、few-shot 数量、答案抽取规则、归一化方式都会改变结果。它的存在本身就是「分数必须连同执行配置一起报」这条纪律的证据。
  - 不能证明：它保证的是执行可复现，不保证任务本身衡量了你关心的能力，也不检测数据污染。
  - `EleutherAI/lm-evaluation-harness` · 版本 v0.4.12（2026-05-11） · MIT · MIT：宽松许可，可整段引用源码并保留出处与版本锚点
- **[HELM：多场景、多指标的整体性评测](https://crfm.stanford.edu/helm/)** — 评测方法学
  - 能证明：单一准确率无法描述模型能力。HELM 的做法是把场景（scenario）与指标（metric）做成正交的两维，同一个场景同时报准确率、校准度、鲁棒性、公平性、效率——「模型 A 比 B 好」这句话必须指明在哪个场景的哪个指标上。
  - 不能证明：覆盖的是公开场景，不覆盖你的业务分布。榜单名次不能迁移到企业任务上。
  - `stanford-crfm/helm` · 版本 v0.5.16（2026-04-30） · Apache-2.0 · Apache-2.0：宽松许可，可整段引用源码并保留出处与版本锚点
- **[SWE-bench：以真实仓库 issue 为任务的 Agent 基准](https://www.swebench.com/)** — 任务级基准
  - 能证明：任务级评测的判据可以完全确定：补丁应用后跑原仓库的测试，通过即算解决。这比模型评判可靠得多，也说明「只要任务本身自带 oracle，评测就不需要 judge」。
  - 不能证明：任务来自公开仓库，训练数据污染无法排除；单次成功率也不代表在你私有代码库上的表现。执行成本高，不适合做每次提交的门禁。
  - `SWE-bench/SWE-bench` · 版本 v4.1.0 · MIT · MIT：宽松许可，可整段引用源码并保留出处与版本锚点
