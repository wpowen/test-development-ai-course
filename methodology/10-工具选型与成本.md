# 10 工具选型与成本模型

## 10.1 选型前的三条纪律

1. **先有方法，再选工具**。工具解决"怎么做得更快"，不解决"该做什么"。没有测试策略就选工具，等于先买设备再想开什么厂。
2. **本手册不推荐任何具体产品**。下表列出的是**能力域与工具类别**；具体产品由你按 10.3 打分表自行评估。
3. **工具数量不是能力指标**。引入一个工具的真实成本 = 采购 + 集成 + 培训 + 维护 + 迁移退出成本。

## 10.2 能力域 → 工具类别映射

| 能力域 | 工具类别 | 必须具备的能力 | 常见坑 |
| --- | --- | --- | --- |
| 依据与追溯 | 需求管理 / 追溯矩阵 | 稳定 ID、版本、双向链接、API 可读 | 只有 UI 没有 API，无法自动化门禁 |
| 契约测试 | 契约/Schema 校验 | 消费者驱动、破坏性变更检测 | 只校验生产者，漏掉消费者兼容 |
| 接口自动化 | HTTP/事件测试框架 | 断言可组合、支持异步与幂等验证 | 只断言状态码 |
| UI 自动化 | 浏览器/移动自动化 | Trace/截图、网络控制、隔离账户 | 定位器脆弱、无业务 Oracle |
| 属性/变形测试 | property-based 框架 | 可自定义生成器与收缩 | 只用默认生成器，覆盖不到业务边界 |
| 变异测试 | mutation 框架 | 可插拔变异算子、区分 no-coverage | 只对代码变异，不对数据/Prompt 变异 |
| 故障注入 | 混沌/故障注入 | 可控爆炸半径、可回滚 | 在共享环境注入影响他人 |
| 评测（AI） | eval 框架 | 数据集版本、切片、重复运行、Judge 可换 | 把 Judge 硬编码，无法校准 |
| Trace/可观测 | 分布式追踪 | span 级、可关联 run_id、成本字段 | 采样率过低，关键失败没记录 |
| 提示词管理 | Prompt 版本管理 | 版本、diff、与 eval 绑定 | 用文档管理 Prompt，无法进门禁 |
| 数据管理 | 数据集/脱敏 | 快照 ID、脱敏审计、切片 | 脱敏后仍可再识别 |
| 环境管理 | IaC / 临时环境 | 可重建、自动回收、成本归属 | 没有回收，成本失控 |
| 安全测试 | 扫描 + 攻击集 | 可自定义载荷、支持间接注入 | 只测直接注入 |
| 性能 | 负载生成 | 可建 token 分布、流式支持 | 用固定长度压测 AI 服务 |
| 门禁编排 | CI/CD | 分层、fail-closed、可追溯产物 | 失败被当作跳过 |
| 缺陷管理 | 缺陷跟踪 | Severity/Priority 分离、可挂 run_id | 两个字段合并 |

## 10.3 工具选型打分表

对每个候选独立打分（1–5），乘以权重。**权重必须先定，再看候选**，否则会被现有偏好带跑。

| 维度 | 说明 | 建议权重（可调） |
| --- | --- | --- |
| 契合方法 | 能否支撑本手册要求的工件与门禁 | 5 |
| 可脚本化 | 有无 CLI/API，能否进流水线 | 5 |
| 证据可追溯 | 输出是否含版本、run_id、原始结果 | 5 |
| fail-closed | 异常时是否阻断而非跳过 | 4 |
| 可替换性 | 数据与配置能否导出、迁移成本 | 4 |
| 团队上手成本 | 现有能力能否覆盖 | 3 |
| 集成成本 | 与现有 CI/追踪/缺陷系统 | 3 |
| 维护与社区 | 更新频率、问题响应 | 3 |
| 成本 | 许可 + 运行 + 人力 | 3 |
| 安全与合规 | 数据外发、审计、驻留 | 5 |

**否决项（任一命中即淘汰，不进入打分）**：

```text
✗ 无法导出原始结果（只有汇总分）
✗ 无法固定版本（只有"最新"）
✗ 强制把测试数据外发到不可控环境
✗ 无法在失败时返回非零退出码
```

## 10.4 自建 vs 采购

| 情况 | 倾向 | 理由 |
| --- | --- | --- |
| 业务 Oracle、风险模型、评测集 | **自建** | 这是你的核心资产，外部工具无法替代 |
| 通用执行器（HTTP、浏览器、负载） | 采购/开源 | 已经很成熟，自建无收益 |
| 追踪、缺陷、CI | 采购/开源 | 同上 |
| 评测编排与门禁胶水 | **自建薄层** | 需要贴合你的门禁语义与状态词 |
| Judge 模型 | 采购但**自建校准** | 模型可换，校准集是资产 |

原则：**把资产建在数据与判据上，把工具建在可替换的执行层上。**

## 10.5 成本模型

### 10.5.1 成本构成

```text
质量总成本 = 预防成本 + 检测成本 + 内部失败成本 + 外部失败成本
```

| 类别 | 包含 | 特点 |
| --- | --- | --- |
| 预防 | 依据冻结、契约化、可测试性评审、培训 | 投入早，回报大 |
| 检测 | 用例、自动化、评测、环境、模型调用费 | 可优化，但不可省 |
| 内部失败 | 发布前发现缺陷的返工 | 越早越便宜 |
| 外部失败 | 逃逸缺陷、事故、赔付、信任损失 | **最贵，且不完全可量化** |

### 10.5.2 AI 特有成本项（传统项目没有）

| 成本项 | 计量 | 控制手段 |
| --- | --- | --- |
| 模型调用费（评测） | token × 单价 × 重复次数 × 样本数 | 默认录制回放；真实调用只在指定层 |
| Judge 调用费 | 同上 | 分层判定：规则先筛，Judge 只处理剩余 |
| 人工标注 | 人时 × 样本数 | 主动学习式抽样，不做全量标注 |
| 人工抽检 | 人时 × 频率 | 只抽高风险切片 |
| 向量索引重建 | 计算 + 存储 | 分块策略稳定后再规模化 |
| GPU 测试环境 | 时长 × 单价 | 严格自动回收 |
| 长期证据存储 | Trace + 原始输出 | 分级保留（blocker 长留，正常样本短留） |

### 10.5.3 评测预算控制

评测成本会随"样本数 × 重复次数 × 切片数 × 候选版本数"四重相乘迅速失控。控制顺序：

```text
1. 分层过滤：先跑成本最低的 Oracle（L1–L4），只有通过的样本才进 L5/L6
2. 分层数据集：冒烟集(小) → 日常集(中) → 完整集(大) → holdout(仅发布)
3. 重复次数按风险分配：blocker 切片重复 N 次，普通切片重复 1–2 次
4. 缓存：相同输入 + 相同版本的结果可复用，但必须记录缓存命中
5. 预算护栏：单次评测设 token/费用上限，超限中止并报告，而不是静默截断
```

⚠ 缓存命中率不一致会破坏 A/B 可比性。A/B 实验必须**关闭缓存或强制两侧命中率一致**。

### 10.5.4 单位成功成本

```text
单位成功成本 = (模型费 + 工具费 + 人工复核费) / 成功完成的任务数
```

这是 AI 系统最有决策价值的经济指标：它能同时暴露"质量下降"（分母减小）和"成本上升"（分子增大），而单看 token 费用两者都看不出来。

**用法**：任何架构变更（单 Agent → 多 Agent、换模型、加检索）都必须报告变更前后的单位成功成本，并在**同预算、同任务集**下对比。
