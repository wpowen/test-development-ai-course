# 01 公理与责任模型

## 1.1 八条方法论公理

这八条是本手册所有流程、模板与门禁的推导起点。任何具体做法与公理冲突时，以公理为准。

### 公理 1：测试的产出是**可复现的证据**，不是"通过"

一句"回归通过了"没有信息量。可交付的最小单位是一份 **Run Receipt**：谁、在哪个版本、用什么输入、跑出什么结果、由谁判定、剩余风险是什么。没有 Run Receipt 的绿色只是一次口头承诺。

> 反例：CI 显示绿色，但没人能说出它跑的是哪个模型版本、哪份数据集、Judge 是哪一版。这条流水线不产生证据。

### 公理 2：**结构正确 ≠ 语义正确**

JSON Schema 校验通过，只说明"程序能解析"。它不说明业务规则被正确理解、引用真实存在、副作用可接受。二者必须是**两道独立门禁**，分别命名为 `PASS_SCHEMA` 与 `PASS_SEMANTIC`，不允许合并成一个"通过"。

### 公理 3：**冲突与未知必须显式阻断，不得被静默合并**

当两份有效来源互相矛盾，正确结果不是让模型"综合判断出更合理的一条"，而是产出 `BLOCKED` 并指名冲突双方与升级责任人。文档没写的内容产出 `UNKNOWN`，不允许补写。

> 模型"选一个更合理的说法"= 把模型变成了没有授权的产品负责人。

### 公理 4：**被测者不能批准自己**

模型不能做自己输出的 Oracle；LLM-as-judge 不能评判自己生成的参考答案；自愈测试（healer）不能修改业务断言；生成用例的 Agent 不能宣布自己的用例有检测力。检测力只能由**独立 Oracle** 或**变异/故障注入**证明。

### 公理 5：**权限在工具边界执行，不在 Prompt 里请求**

"请不要越权"是一句话，不是一个控制。身份、租户、最小 scope、参数边界、幂等键、人工审批必须在**可写副作用发生之前**由代码强制执行。模型拒绝了恶意指令是好事，但不构成安全结论。

### 公理 6：**成熟度只能向上证明，不能向上声称**

五级阶梯（见 1.4）之间不存在自动升级。fixture 全绿不能写成"真实模型可用"；离线评测漂亮不能写成"生产有效"。任何升级都需要对应层级的**新鲜运行证据**。

### 公理 7：**一次只改一个变量**

同时更换模型、Prompt 和索引后分数上涨，这个结果不可归因、不可回滚、不可复用。A/B 必须锁定除被比较项以外的全部字段；两个锁定字段同时变化时实验标记为 `confounded` 并作废。

### 公理 8：**降低阈值不是修复**

调低阈值、删除断言、扩大权限、无限重试、加长超时都属于制造假绿。任何放行都必须走 **Waiver 流程**：具名负责人、原因、补偿控制、过期时间、回滚条件，五项缺一不可。

## 1.2 责任与决策权模型

测试开发的职业责任**不是**保证零缺陷，**也不是**统计执行了多少条用例。它是三件事：

1. 尽早识别影响用户与业务的质量风险；
2. 把规则与未知转成**可测试依据**，把结果转成**可复现证据**；
3. 让具名责任人能够作出发布、Waiver、回滚或继续投入的决定。

### 决策权归属表

一个人可以兼任多个角色，但角色对应的**决定权不能消失**。

| 决定 | 唯一裁决者 | 测试开发的动作 | 不允许发生的事 |
| --- | --- | --- | --- |
| 业务规则是什么 | 产品 / 业务 owner | 提出冲突、标记 `BLOCKED`、给出影响面 | 测试或模型自行裁定"更合理"的规则 |
| 实现方案与技术权衡 | 研发 / 架构 owner | 提出可测试性缺口、不可观测点 | 把实现选择当成需求写进用例 |
| 风险是否值得测、测到什么程度 | 测试开发（本职） | 出具风险登记册与测试策略 | 按"用例数量"或"工具数量"定质量 |
| 关键金额 / 权限 / 状态的正确性 | 领域 owner | 提供独立 Oracle 与证据 | 让 LLM Judge 单独放行 |
| 是否发布、是否接受剩余风险 | 发布 owner | 呈现证据与残余风险清单 | 测试代替发布 owner 说"可以发" |
| 是否回滚、生产如何处置 | SRE / 运行负责人 | 提供 Trace、影响面与回归用例 | 无回滚预案就上线 |
| 安全例外是否批准 | 安全 owner | 提供攻击面与暴露范围 | 用 Prompt 声明代替权限控制 |

完整 RACI 见 [09-组织角色与能力.md](09-组织角色与能力.md)。

## 1.3 AI 授权边界（可做 / 需复核 / 不可做）

这张表是所有 Prompt 的权限声明来源。写 Prompt 时把对应行直接抄进 System 段。

| 类别 | AI **可以自主做** | 必须**人工复核**后才生效 | AI **不可做** |
| --- | --- | --- | --- |
| 需求与文档 | 抽取、分类、切分、候选冲突识别、术语归一 | 需求契约的业务语义、优先级裁定 | 新增/修改业务规则、裁决冲突、补写缺失政策 |
| 风险 | 生成候选风险清单、按历史缺陷聚类 | 风险等级与测试深度 | 决定不测某个风险 |
| 用例设计 | 生成候选用例、补边界值、生成组合 | 业务 Oracle、期望值 | 宣布自己的用例有检测力 |
| 数据 | 生成合成数据、脱敏建议、切片划分建议 | Holdout 封存、数据授权 | 使用真实生产个人信息 |
| 自动化 | 生成脚手架代码、定位器候选、重构建议 | 断言语义、合并 | 删除断言、修改期望值、跳过步骤 |
| 执行归因 | 失败聚类、候选根因、日志摘要 | 根因确认、缺陷分级 | 把 `UNKNOWN` 写成一个"听起来合理"的根因 |
| 评测 | 结构校验、规则 Oracle、批量打分 | Judge 校准结果、阈值 | 评判自己的输出；批准自己的 reference |
| 发布 | 汇总证据、生成报告草稿 | 全部 | 作出发布/Waiver/回滚决定 |
| 安全 | 生成攻击载荷候选、扫描面枚举 | 暴露范围结论 | 批准安全例外、绕过授权 |

**状态语义**（所有 AI 调用统一使用；完整命名空间见 [`status-model.schema.json`](status-model.schema.json)）：

```text
EVIDENCED       有来源支持；这只是事实状态，不等同于执行通过
UNKNOWN         文档未定义；不得补写，进入 open questions
CONFLICTING     多源证据冲突；停止受影响风险决策，等待优先级裁定
NOT_RUN         尚未执行；不得写成 PASS 或证据不足
PASS / FAIL     有可追溯运行收据的执行结果
BLOCKED         关键状态不可观察 / 越权 / 依赖未满足；停止受影响下游
REFUSED         模型拒答；是显式状态，不得当作空结果或 PASS
INCOMPLETE      被截断；同上
SCHEMA_INVALID  结构不合法
UNSUPPORTED_RULE 输出了没有来源的规则
PASSED / WAIVED 门禁通过 / 有权 owner 的正式豁免；WAIVED 不会把 UNKNOWN 变成证据
SUPERSEDED      被更新的可复现证据推翻（记录生命周期）
```

传播规则：`UNKNOWN` 可被登记，但必须带 `unknown_class`、`stage`、`risk_level`、`unknown_scope`、`owner`、`next_evidence`、`expires_at` 和 `escalation_action`。低/中风险的 `DISCOVERY` 只允许在 S1/S2 继续结构化；`DECISION_CRITICAL` 或任何控制发布、风险裁决、Oracle、准出条件的未知，必须阻断该决策的关闭并升级给 owner，直至消解或由有权 owner 正式 Waiver。任一上游为 `CONFLICTING`、`BLOCKED`、`REFUSED`、`INCOMPLETE`、`SCHEMA_INVALID` 或 `UNSUPPORTED_RULE` 时，受影响的下游生成、评分与发布**一律停止**，不得降级为警告。不同命名空间不可互相替代：事实被证实不等于门禁通过，夹具 `PASS` 也不等于真实模型或生产成熟度。

## 1.4 证据成熟度阶梯

五级，只能逐级向上证明。每一级都有**唯一的升级证据**要求。

| 级别 | 含义 | 升级所需的新鲜证据 | 允许的表述 | 禁止的表述 |
| --- | --- | --- | --- | --- |
| **L0 `desk-researched`** | 只有资料综合与设计 | 来源可追、方法自洽 | "方案设计如下" | "已验证" |
| **L1 `fixture-tested`** | 确定性离线夹具跑通，红绿可复现 | baseline / fault / repair 三段报告 + 精确退出码 | "流程可运行、预埋缺陷能被发现" | "模型可用" |
| **L2 `model-integrated`** | 接入真实模型跑通 | provider / model / 参数 / 输入 hash / 原始输出 / Scorer 版本可追 | "在 X 模型 Y 版本上得到 Z 分布" | "模型准确率是 Z" |
| **L3 `integration-tested`** | 接入真实企业系统 | 真实 API / 权限系统 / 流水线的运行收据 | "在本环境集成通过" | "生产可用" |
| **L4 `practitioner-reviewed`** | 具名从业者盲评通过 | 评审人姓名/角色、盲评设计、意见原文 | "N 位从业者认可" | "行业标准" |
| **L5 `production-validated`** | 生产运行验证 | 生产指标前后对照、影响面、回滚记录 | "生产上观察到 …" | 无 |

**当前项目状态**：课程与本手册整体位于 **L1**。L2–L5 全部为 `NOT_RUN`。

## 1.5 三类断言的分离

写任何结论时，必须把三类内容分开标注，不允许混排：

- **Evidence**：来源直接支持，可给出出处与版本。
- **Inference**：跨来源综合得出的工程判断，需 owner 接受。
- **Unknown**：当前证据无法回答，需列出"用什么实验可以回答"。

模板见 `templates/18-evidence-boundary-statement.md`。

## 1.6 常见反模式速查

| 反模式 | 表现 | 正确做法 |
| --- | --- | --- |
| 用例数崇拜 | 用"新增 800 条用例"汇报质量 | 报告风险覆盖与变异杀死率 |
| 平均分掩盖 | 总分上升即发布 | 按风险切片单独设 blocker |
| 单次运行结论 | 跑一次就下判断 | 重复运行 + 分布 + 区间 |
| Prompt 当控制 | 在提示词里写"不要越权" | 在工具边界执行授权 |
| 模型自证 | 让模型评自己的输出 | 独立 Oracle / 变异 / 人工 |
| 静默合并冲突 | 模型挑一个更合理的说法 | `BLOCKED` + 升级 |
| 假绿修复 | 改期望值让测试变绿 | 保留原 Oracle，重跑变异 |
| 成熟度冒充 | fixture 全绿写成"已验证" | 按 1.4 阶梯逐级声明 |
