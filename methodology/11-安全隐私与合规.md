# 11 安全、隐私与合规

本章只覆盖**测试开发在质量流程中必须承担的部分**。渗透测试、合规认证、法务判定不在本手册范围，需由安全 owner 与法务负责。

## 11.1 信任边界模型

AI 系统最重要的一条认知：**模型的输出永远是不可信候选**，检索到的内容、工具返回值、用户输入同样不可信。

```text
        ┌──────────────── 不可信区 ────────────────┐
        │  用户输入   网页/邮件   知识库文档   工具返回值  │
        └───────────────────┬──────────────────────┘
                            │ 只作为「数据」进入
                    ┌───────▼────────┐
                    │   模型推理层    │  ← 输出仍是不可信候选
                    └───────┬────────┘
                            │ 候选动作
        ┌───────────────────▼──────────────────────┐
        │  授权层（模型之外）：身份 → 租户 → scope   │
        │  → 参数边界 → 幂等 → 人工审批             │
        └───────────────────┬──────────────────────┘
                            │ 只有通过才执行
                    ┌───────▼────────┐
                    │  可写副作用     │
                    └────────────────┘
                            │
                    ┌───────▼────────┐
                    │  输出 DLP 过滤  │  ← 最后一道，不能替代授权
                    └────────────────┘
```

**核心原则**：授权在**模型之外**完整中介。模型拒绝了恶意指令是好事，但不构成安全结论。

## 11.2 必测攻击面

| 攻击类别 | 载体 | 测试要点 | Blocker 判据 |
| --- | --- | --- | --- |
| 直接注入 | 用户输入 | 覆盖系统指令、越权请求 | 产生越权动作 |
| **间接注入** | 网页、邮件、知识库、工具返回、文件名 | 污染内容能否改变执行 | 到达工具层 |
| MCP / 工具投毒 | 工具描述、协议 | 工具描述被篡改后行为 | 调用被篡改工具 |
| 越权调用 | 身份/scope | 未验证身份即可写 | 任一次发生 |
| 跨租户 | 检索/记忆/缓存 | A 租户数据出现在 B | 任一次发生 |
| 敏感泄露 | 输出、日志、Trace | 密钥、个人信息、内部路径 | 任一次发生 |
| 过度代理权 | 工具集合 | 是否具备超出任务的能力 | 有不必要的可写工具 |
| 委托链滥用 | 子 Agent / Handoff | 权限是否随交接扩大 | 下游权限 > 上游 |
| 记忆污染 | 长期 Memory | 恶意内容被持久化并复用 | 跨会话影响 |
| 语义缓存投毒 | 缓存 | 污染条目被命中 | 命中污染结果 |
| 供应链 | 依赖、模型、插件 | 版本固定、来源可信、签名 | 引入未审依赖 |

### 攻击集的最小结构

```text
attacks/
├── direct/          直接注入载荷
├── indirect/        嵌入文档/网页/邮件的载荷
├── cross-tenant/    跨租户读取尝试
├── privilege/       越权与提权
├── exfiltration/    敏感信息外泄
└── expectations.json  每条载荷的期望结果（被哪一层拦下）
```

**关键设计**：期望结果不能只写"被拒绝"，必须写**被哪一层拦下**——模型拒绝与授权层拒绝是完全不同的安全等级，报告中必须分开统计。

## 11.3 测试数据的隐私红线

### 绝对禁止（无例外）

```text
✗ 在测试中使用未脱敏的真实个人信息
✗ 在测试中使用真实支付账号、银行卡、身份证件号
✗ 在测试中使用生产密钥、真实 token
✗ 把生产数据发送到不可控的外部模型 API
✗ 在 Prompt、日志、Trace、缺陷记录中残留敏感字段
```

### 脱敏的三个层次

| 层次 | 做法 | 适用 | 风险 |
| --- | --- | --- | --- |
| 遮蔽 | 替换为 `***` | 展示类 | 破坏格式，可能改变行为 |
| 假名化 | 一致性替换（同一原值→同一假值） | 需要关联的场景 | **可被再识别** |
| 合成 | 按分布重新生成 | 大部分测试 | 分布可能失真 |

⚠ 假名化**不等于**匿名化。当准标识符组合（年龄+地区+时间）足以定位个人时，仍属个人信息。涉及此类数据必须由数据 owner 与合规判定。

### 数据处理记录（每个数据集必填）

```text
数据集 ID        : <id>
来源             : 合成 / 脱敏生产 / 人工标注 / 公开数据集
个人信息         : 有 / 无（若有，列出字段类别）
脱敏方式与版本   : <方式> / <规则版本>
授权             : <授权人> / <授权日期> / <授权范围>
存储位置与保留期 : <位置> / <天数>
可外发           : 是 / 否（可外发至哪些服务）
销毁方式与责任人 : <方式> / <姓名>
```

## 11.4 证据留痕与审计

质量流程本身也要可审计。以下内容必须留痕且**不可被静默修改**：

```text
□ 每次门禁结果（含失败）与 run_id
□ 每次 Waiver：内容、批准人、时间、过期时间
□ 每次阈值/切片定义变更：变更人、原因、前后值
□ 每次 holdout 开封：时间、目的、批准人
□ 每次生产写权限授予：申请人、范围、时长、审批人
□ 每次数据授权与销毁
□ 每次安全例外批准
```

**保留期**（占位，按合规要求设定）：门禁结果 ≥ 1 个发布周期；Waiver 与安全例外 ≥ 审计周期；含个人信息的记录按数据处理记录中的保留期，到期自动销毁。

## 11.5 高风险场景的额外门禁

当被测系统涉及以下任一项时，最低门禁自动升级为"关键"档：

```text
· 资金转移、退款、支付、结算
· 权限授予、身份变更、账户操作
· 医疗、法律、金融等专业建议
· 未成年人相关
· 个人信息批量处理
· 不可逆的对外动作（发送、发布、下单、注销）
```

额外要求：

1. **必须有人工确认环节**，且确认信息要足以让人作出判断（不能只显示"确认执行？"）；
2. **必须有能力沙箱**：即使模型完全被劫持，可造成的最大损失有明确上限；
3. **必须有独立于模型的规则 Oracle**，L5 语义层不得单独放行；
4. **必须演练回滚与对账**。

## 11.6 确认疲劳（AI 特有的人因风险）

给 Agent 加一堆"请确认"看起来安全，实际上会制造新的失效模式：人在第 20 次确认时会闭眼点同意。

**必测**：

```text
□ 确认次数：单任务人工确认次数是否在可接受范围
□ 确认信息质量：是否包含足以判断的关键信息（对象、金额、影响面、不可逆性）
□ 默认值安全：确认框的默认选项是否是安全选项
□ 批量确认：是否存在"全部同意"绕过逐项判断
□ 疲劳实验：连续任务下的确认正确率变化
```
