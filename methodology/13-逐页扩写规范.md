# 13 逐页扩写规范

本规范用于把 103 页课程从"提纲密度"提升到"交付密度"。它是课程作者的验收标准，也是后续批量扩写的基准。

## 13.1 问题诊断（2026-08-12 实测）

对 `tutorial/tutorial-site.json` 的 102 页历史快照（2026-08-12 实测；当前目录为 103 页）的中文正文字符统计：

| 分位 | 中文字符数 |
| --- | --- |
| 最小 | 935（TD-AP03） |
| P25 | 1157 |
| **中位** | **1287** |
| P75 | 1535 |
| 最大 | 6424（TD-F01） |

标称 45–60 分钟的页面，正文中位只有约 1300 字。同时 `site/scripts/validate-content.ts` 的厚度门槛是 `JSON.stringify(page.blocks).length < 750`——**门禁只能挡住空页，挡不住薄页**。这是"结构全绿但内容不达标"的机制性原因。

另外两个已知问题：

1. **模块内同质化**：每个模块用自己的 builder 生成页面，块标题与部分正文逐页复用（独立 editorial 已记录 Agent 11 页实质句重复 82%）。
2. **死代码模板**：`site/content/modules/topic-page.ts` 的 `buildTopicPage` 无任何模块引用，且会写入 fail-closed 的 legacy `code` 字段，对后续作者是误导。

## 13.2 扩写后的页面必须包含的十二个部分

| # | 部分 | 最低要求 | 为什么必须有 |
| --- | --- | --- | --- |
| 1 | 一句话结论 | ≤ 40 字，说清"这页解决什么判断" | 读者要在 10 秒内知道是否该读 |
| 2 | 术语前置 | 本页首次出现的术语，逐个一句话解释或链到 02 章 | 小白卡在术语上就读不下去 |
| 3 | 真实问题 | 具体到角色、系统、后果、金额或影响面 | 抽象问题无法迁移 |
| 4 | 心智模型 | 一段"把它想成 X"的类比 + 一张图 | 概念要先落地才能记住 |
| 5 | 方法步骤 | 编号步骤，每步含：输入 / 动作 / 输出 / 判据 | 缺判据的步骤不可执行 |
| 6 | **判断表** | 至少一张"如果…则…"的选择表 | 这是方法论与教程的分界线 |
| 7 | 正例 | 完整、可复制、可运行 | "示意代码"不可用 |
| 8 | **反例** | 至少 2 个，且说明它为什么看起来对 | 只给正例学不会判断 |
| 9 | 失败诊断树 | 症状 → 可能层 → 下一步检查 | AI 系统的定位成本是主要成本 |
| 10 | 可复用工件 | 指向真实存在的模板/脚本/Schema 文件 | "拿到就能用"的实体 |
| 11 | 迁移说明 | 哪些不变、哪些必须改（至少 2 项配置） | 防止照抄失败 |
| 12 | 证据边界 | 本页结论的成熟度与未验证项 | 防止越界声称 |

## 13.3 量化门槛

| 指标 | 当前 | 目标 | 说明 |
| --- | --- | --- | --- |
| 中文正文字符 | 中位 1287 | **≥ 3000**（概念页）/ **≥ 4000**（跟做页） | 与标称时长匹配 |
| 判断表 | 多数页 0–1 | ≥ 1 | 表是方法论的骨架 |
| 反例 | 多数页 0 | ≥ 2 | 且需说明"为什么看起来对" |
| 失败诊断项 | 1 段文字 | ≥ 4 条症状→动作 | 可查表定位 |
| 可复制工件 | 5–7 个 material（多为共享 manifest） | ≥ 1 个**页面专属**可复制文本块 | 页面级而非 bundle 级 |
| 跨页重复句率 | Agent 模块 82% | **≤ 20%** | 模块内 builder 生成句必须参数化 |

## 13.4 扩写工作流（每页）

```text
1. 读该页的 research/topics/<ID>/ 九件研究包 → 提取尚未落到正文的事实
2. 按 13.2 的十二部分列骨架，标出当前缺哪几部分
3. 补 3/6/8/9 四项（真实问题、判断表、反例、诊断树）—— 这四项收益最高
4. 补 10：为该页写一个页面专属的可复制工件（模板片段/Schema/检查单）
5. 跑重复句检测：与同模块其它页做句级比对，重复率 > 20% 的句子改写
6. 跑 validate:content、audit:executability
7. 更新 tutorial 投影并核对 sync-tutorial-package --check
```

## 13.5 建议的门禁增强

当前 `validate-content.ts` 只检查 `< 750 chars`。建议增补以下检查（改动点已标出）：

```text
site/scripts/validate-content.ts
  · 新增：中文正文字符下限（概念页 3000 / 跟做页 4000）
  · 新增：至少一张 table（判断表）
  · 新增：跨页句级重复率上限 20%（同模块内比对）
  · 新增：至少一个页面专属 material（href 不与同模块其它页完全相同）
```

⚠ **不要一次性把门槛提到目标值**——那会让 103 页全部变红且无法发布。推荐做法：

1. 先把门槛设为当前实测的 P25（1157），确保不倒退；
2. 每完成一个模块的扩写，把门槛提升到已完成模块的最低值；
3. 全部完成后再提到目标值。

## 13.6 扩写优先级

按"读者最先遇到 × 当前最薄"排序：

| 优先级 | 模块 | 页数 | 当前中位字符 | 理由 |
| --- | --- | --- | --- | --- |
| P0 | TD-M00 完整测试生命周期 | 8 | ~2000 | 全课程骨架，所有人必读 |
| P1 | TD-M12 Agent 测试架构 | 11 | ~1030 | 最薄且重复率最高 |
| P1 | TD-M11 Agent 性能与稳定性 | 8 | ~990 | 最薄 |
| P2 | TD-M01 AI 基础 / TD-M03 LLM+RAG | 21 | ~1300 | 概念密集，小白最易卡 |
| P2 | TD-M08 传统测试专项 | 12 | ~1450 | 已有 material 支撑，补正文即可 |
| P3 | 其余模块 | 42 | ~1300 | — |

## 13.7 清理项

```text
□ 删除 site/content/modules/topic-page.ts 中未被引用的 buildTopicPage
  （或改为抛错的占位，防止新作者误用 legacy code 字段）
□ 把各模块 builder 中的固定句参数化，避免同质化
□ 把 validate-content.ts 的 bannedGenericPhrases 扩展到新的通用句
```
