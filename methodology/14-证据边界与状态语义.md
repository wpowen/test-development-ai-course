# 14 证据边界与状态语义

## 14.1 本手册自身的成熟度声明

| 内容 | 等级 | 依据 | 不得声称 |
| --- | --- | --- | --- |
| 方法论骨架（S1–S9、六层 Oracle、五级成熟度） | **Inference** | 由 `research/methodology/route-a-standards.md`、`route-b-practice.md`、`comparison-and-factory-contract.md` 综合推导 | "行业标准"、"某标准要求" |

| 工具类别表 | **Inference** | 能力域分类，非产品评测 | 推荐/背书任何产品 |

| 职级、年限、薪酬 | **不在范围** | — | 任何相关表述 |

**整体等级：L1 `fixture-tested`。L2–L5 全部 `NOT_RUN`。**

## 14.2 未验证项清单（明确列出，防止越界）

```text
NOT_RUN  真实模型上的抽取准确率、跨模型/跨版本稳定性
NOT_RUN  真实企业 API、权限系统、CI/CD、K8s 的集成运行
NOT_RUN  目标组织的流程适配效果
NOT_RUN  具名测试开发从业者的盲评意见
NOT_RUN  目标学习者（小白）的完成率与迁移成功率
NOT_RUN  生产环境的缺陷逃逸率变化、成本变化、事故率变化
NOT_RUN  本手册阈值结构在任何真实业务上的校准结果
```

## 14.3 状态词的唯一语义

手册、课程、验证器、报告必须使用同一套词。以下是唯一允许的定义：

| 状态词 | 唯一含义 | 常见误用 |
| --- | --- | --- |
| `PASS_SCHEMA` | 结构合法 | 被写成"通过" |
| `PASS_SEMANTIC` | 业务语义经确认 | 被结构通过顶替 |
| `PASS-FIXTURE` | 确定性夹具上 0/1/0 通过 | 被写成 `PASS-LIVE` |
| `PASS-LIVE` | 真实模型上通过 | 被 fixture 结果冒充 |
| `PASS-PRACTITIONER` | 具名从业者评审通过 | 被自评冒充 |
| `PASS-PRODUCTION` | 生产验证通过 | 被预发结果冒充 |
| `BLOCKED` | 冲突/不可观察/越权，下游停止 | 被降级为警告 |
| `UNKNOWN` | 证据不足，需人工或新实验 | 被补写成合理根因 |
| `REFUSED` | 模型拒答（显式状态） | 被当作空结果或 PASS |
| `INCOMPLETE` | 输出被截断 | 同上 |
| `NOT_RUN` | 从未执行 | 被省略不写 |
| `SUPERSEDED` | 被更新的可复现证据推翻 | 旧结论继续被引用 |
| `QUARANTINE` | Flaky，保留运行但不阻断 | 被直接删除 |
| `EXPLORATORY` | 无法追溯到需求的测试 | 被计入需求覆盖 |

## 14.4 冲突裁决规则

1. **较新的可复现证据优先**。冲突时以新鲜运行结果为准，并显式把旧状态标记为 `SUPERSEDED`。
2. **较低成熟度不得覆盖较高成熟度的否定结论**。fixture 通过不能推翻一次真实集成失败。
3. **门禁失败优先于任何汇总分**。单个 blocker 切片失败即阻断，无论总分多高。
4. **人工否决优先于自动通过**；自动否决不得被人工"觉得没问题"直接放行，只能走 Waiver。

## 14.5 本手册的更新规则

```text
· 任何数值从"占位"变为"实测"时，必须同时记录：样本量、周期数、采集时间、责任人
· 任何 Inference 升级为 Evidence，必须附来源与版本
· 任何成熟度升级，必须附对应等级的新鲜运行证据（见 01 章 1.4）
· 每次更新写入 update-log，并标注被 SUPERSEDED 的旧结论
```

## 14.6 引用本手册时的正确表述

✅ 可以说：

- "按本手册的 S1–S9 流程组织测试"
- "本手册建议的结构是……，阈值需按本团队实测设定"
- "该结论目前为 L1 fixture-tested，真实模型未验证"

❌ 不能说：

- "根据行业标准，变异杀死率应达到 80%"
- "本方法论已验证可降低 X% 的缺陷逃逸"
- "该工具是推荐选型"
- "L3 工程师应具备 5 年经验"
