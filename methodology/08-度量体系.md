# 08 度量体系与质量报表

## 8.1 度量的第一原则

> **一个指标如果不能改变任何决定，就不要度量它。**

每个指标必须绑定：**它回答哪个决定？谁看？超阈值时做什么？** 三者缺一的指标一律删除。

反面清单（这些指标本身不可作为质量结论）：

| 常见但无效的指标 | 为什么无效 | 替代 |
| --- | --- | --- |
| 用例总数 | 数量与检测力无关 | 变异杀死率 |
| 自动化率 | 自动化了错的东西更糟 | 高风险自动化覆盖率 |
| 代码行覆盖率 | 执行过 ≠ 会被发现 | 变异杀死率 + 风险覆盖 |
| 缺陷总数 | 受投入与阶段影响 | 缺陷逃逸率 + 逃逸严重度 |
| 评测平均分 | 掩盖高风险切片 | 分切片 blocker rate |
| 单次通过率 | 非确定性系统无意义 | 重复运行分布与区间 |
| 测试执行时长 | 与价值无关 | 反馈时延（提交→结论） |

## 8.2 指标目录

分四组。每组给出定义、计算口径、决策用途、常见作弊方式。

### A 组：检测力（测试本身好不好）

| 指标 | 定义 | 计算 | 决策用途 | 作弊方式 |
| --- | --- | --- | --- | --- |
| 变异杀死率 | 被杀死变异 / 总变异 | `killed / (killed + survived)`，排除 `no-coverage` | 判断用例是否有检测力；AI 生成用例必测 | 只植入极易发现的变异 |
| 风险覆盖率 | 已有测试的风险 / 登记风险 | 按 RPN 档位分别计算 | 判断策略是否落地 | 把风险登记得很少 |
| 故障注入通过率 | 0/1/0 三段全部符合的用例比例 | — | 判断门禁是否有牙齿 | 注入无害故障 |
| 逃逸拦截率 | 逃逸缺陷中"本应被现有门禁拦下"的比例 | 事后归因 | 判断门禁配置问题 | 归因时都写"新场景" |

### B 组：AI 质量（被测系统好不好）

| 指标 | 定义 | 计算 | 决策用途 | 作弊方式 |
| --- | --- | --- | --- | --- |
| Schema 通过率 | 结构合法比例 | — | 传输契约 | 放宽 Schema |
| 引用存在率 | 引用可在证据中找到的比例 | — | RAG 可信度 | 只引用固定文档 |
| 忠实度 | 结论被证据支持的比例 | 蕴含判定 | RAG 核心 | 用同一模型自评 |
| 切片 blocker rate | 各 blocker 切片的失败率 | 分切片统计 | **发布决定** | 缩小切片定义 |
| pass@k | k 次中至少一次成功 | 先按任务报告经验比例和任务级/聚类 bootstrap 区间；只有任务同质、运行独立且成功概率可视为同一 `p`（IID）时，才可用 `1 - (1-p)^k` 作解析近似 | 能力上限 | 用它冒充可靠性，或把非 IID 重复当成解析式输入 |
| **pass^k** | k 次全部成功 | 先报告每任务连续成功的经验比例和任务级/聚类 bootstrap 区间；只有上述 IID/同一 `p` 假设成立时，才可用 `p^k` 作解析近似 | **对用户的承诺** | 用 pass@k 替代，或忽略共享上下文、重试与任务异质性 |
| 拒答正确率 | 期望拒答集上的正确拒答比例 | — | 安全与体验 | 不建期望拒答集 |
| 非确定性幅度 | 重复运行结果的离散度 | 标准差或区间宽度 | 是否可上线 | 只跑一次 |
| 漂移幅度 | 相对发布基线的偏移 | 同数据集对照 | 是否需重训/回滚 | 悄悄更新基线 |

### C 组：效率与经济性

| 指标 | 定义 | 决策用途 |
| --- | --- | --- |
| 反馈时延 | 提交 → 得到质量结论 | 门禁分层是否合理 |
| 定位时长 | 失败 → 定位到层 | 可观测性投入是否有效 |
| 单位成功成本 | 总成本 / 成功任务数 | 架构与模型选型 |
| p95 / p99 延迟 | 尾延迟 | SLO |
| Goodput | 满足 SLO 的成功吞吐 | 容量规划 |
| 环境成本 | 测试环境月度支出 | 临时环境回收策略 |

### D 组：流程健康度

| 指标 | 定义 | 阈值动作（占位） |
| --- | --- | --- |
| 缺陷逃逸率 | 生产发现 / (生产 + 发布前) | 上升 → 门禁复审 |
| Waiver 数与超期数 | 未过期 / 已过期未处理 | 超期 > 0 → 阻断发布 |
| 同门禁连续 Waiver 次数 | — | ≥3 → 门禁本身重新评审 |
| Flaky 用例数与占比 | quarantine 集合大小 | 上升 → 环境或同步问题 |
| UNKNOWN 桶滞留数 | 未归因失败数 | 上升 → 可观测性缺口 |
| 回归回灌闭环率 | 已闭环逃逸 / 全部逃逸 | < 100% → 列入下迭代 |

## 8.3 三张看板

不要做一张"综合大屏"。按读者拆成三张，各自只保留能改变该读者决定的指标。

### 看板 1｜工程师（每次提交后看）

```text
[ Gate-1 结果 ]  [ 失败用例 → 归因层 ]  [ 反馈时延 ]  [ 我的 Flaky ]
```

### 看板 2｜测试负责人（每日看）

```text
[ 风险覆盖率（按档位） ]   [ 变异杀死率趋势 ]
[ 各 blocker 切片失败率 ]  [ UNKNOWN 桶 ]
[ Flaky 趋势 ]             [ Waiver 台账（含超期） ]
```

### 看板 3｜发布 / 管理者（发布点与月度看）

```text
[ 发布决定与剩余风险 ]  [ 缺陷逃逸率与逃逸原因分布 ]
[ 单位成功成本趋势 ]    [ 漂移曲线 ]
[ 回归回灌闭环率 ]      [ 门禁复审建议 ]
```

## 8.4 反作弊规则（必须写进流程）

度量一旦与考核挂钩，就会被优化。以下六条是最低限度的防护：

1. **分子分母都要留痕**：任何比率必须同时展示分子、分母与排除项。
2. **变异集不可由被考核方单独定义**：至少一部分变异由独立方或历史逃逸缺陷生成。
3. **切片定义变更需评审**：缩小 blocker 切片等同于放宽门禁。
4. **基线更新需记录**：漂移基线更新必须有 run_id 与批准人，禁止静默刷新。
5. **holdout 开封次数计数**：开封超过约定次数即作废并重建。
6. **指标不得单独用于个人绩效**：质量指标反映系统，不反映个人。

```text
周期            : <起止日期>

一、结论（三句话内）
   本周质量结论：<可发布 / 有条件发布 / 阻断>
   最大风险    ：<一句话>
   需要决定    ：<需要谁决定什么>

二、检测力
   风险覆盖率（关键/高/中/低）：<%/%/%/%>
   变异杀死率：<%>（分子 <n> / 分母 <n> / 排除 no-coverage <n>）
   新增故障注入：<n> 条，0/1/0 通过 <n> 条

三、AI 质量
   blocker 切片失败率：<切片: %> …
   pass@k / pass^k    ：<k=?, 值>
   非确定性幅度       ：<区间>
   漂移               ：相对基线 <偏移>（基线 run_id: <id>）

四、流程健康
   缺陷逃逸：<n> 条（S1 <n> / S2 <n>），原因分布：<…>
   Waiver ：有效 <n>，超期 <n>（超期即阻断）
   Flaky  ：<n>（较上周 <±n>）
   UNKNOWN 桶：<n> 条滞留

   单位成功成本：<值>（较上周 <±%>）
```

## 8.6 阈值怎么定（不要抄别人的数字）

```text
第 1 步  连续采集 3–5 个稳定周期的实测分布（不设阈值，只观察）
第 2 步  取该分布的 p50 与 p95 作为参考锚点
第 3 步  由风险 owner 决定：阈值设在哪一侧、超阈值做什么
第 4 步  写入《测试策略》，标注"基于 <n> 个周期实测，复评日期 <日期>"
第 5 步  每季度用新数据复评一次
```

⚠ 本手册所有出现的数字（80%、5 次、3 天……）都是**结构占位**，不是建议值。直接照抄会得到一个既不阻断真问题、又天天误报的门禁。

### 阈值治理契约

用 [`governance/threshold-policy.yaml`](../governance/threshold-policy.yaml) 为每一个实际阈值登记 policy ID、来源、适用系统与切片、统计假设、风险 owner、有效期、重标定触发器、waiver 规则和失败动作。它刻意把教学模板标为 `TEMPLATE_NOT_RUN`：在目标系统收集到实测基线并由 owner 批准前，不存在可复制的生产默认值。

若 Judge 参与度量，还必须同时满足 Judge Card 与 Gold-set Card 的校准/暂停条件。指标卡、阈值策略和发布收据使用同一 policy ID；任一字段缺失、scope 变化、有效期届满、模型/Prompt/检索/工具版本变化或关键切片分布漂移时，原阈值不得自动沿用。
