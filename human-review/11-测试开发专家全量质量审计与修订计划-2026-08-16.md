# AI 测试开发课程：全量质量审计与修订计划（2026-08-16）

## 1. 审计结论

**结论：课程已达到“结构化、可追溯、fixture 级可复用的专业课程包”水准，但尚不具备“经真实 AI/企业环境验证、可直接作为生产测试方案”的资格。**

优势是完整的工程骨架，而不是营销式“页数很多”：当前公开学习面为 **103 页、13 个课程模块**；页面—研究包—材料—引用—静态站具有双向投影与 hash 闭包。2026-08-16 复跑 `validate:release`、技术块契约测试和 lint 后，内容/引用投影/公开材料边界均通过；lint 仅保留一条既存 `<img>` 性能 warning。

但不能因此升级成熟度。真实 provider/model、企业集成、具名从业者盲评、目标学员效果与生产结果仍为 `NOT_RUN`。此外，状态机、统计口径、评审独立性、外部标准版本钉扎和历史证据治理存在会误导实践者的缺口。**P0 未关闭前，课程只能保持 `PASS-FIXTURE`，不得用作发布或生产 go/no-go 的依据。**

### 2.2 外部标尺

- [ISO/IEC/IEEE 29119 系列](https://committee.iso.org/sites/jtc1sc7/home/projects/flagship-standards/isoiecieee-29119-series.html)要求把组织/管理/动态测试过程、过程产物和测试设计技术连接起来；课程的“方法—工件—门禁”主链与此方向一致。
- [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)与 [NIST AI 600-1 GenAI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)强调贯穿生命周期的风险治理、部署前 TEVV、记录假设/版本/失败和上线后监控；本课程具备设计骨架，但尚未跑到真实 TEVV。
- [OWASP 2025 LLM/GenAI Top 10](https://genai.owasp.org/llm-top-10/)要求把提示注入、敏感信息、供应链、数据/模型投毒、输出处理、过度代理权限、向量/嵌入等纳入完整应用链路，而非只测模型回答。
- [Google 的安全评测指导](https://ai.google.dev/responsible/docs/evaluation)与[评判模型评估指导](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/evaluate-judge-model)要求以人工标注数据校准 Judge，保留逐样本结果和偏差，而非将模型打分当真值。

## 3. 已验证的核心优点

1. **端到端链路设计强。** 方法论 S1–S9 明确给出 Test Basis、需求/技术契约、风险、Oracle、数据、环境、Run Receipt、Waiver 和回归回灌，见 [生命周期总览](../methodology/03-生命周期总览.md)。这比“测试类型清单”更接近实际测试开发流程。
2. **证据边界诚实。** 课程把 L0–L5 拆开，并明示当前 L1、L2–L5 `NOT_RUN`，见 [公理与责任模型](../methodology/01-公理与责任模型.md)。这避免了把 fixture 绿灯包装成模型/生产成功。
3. **可追溯性和投影完整性高。** 2026-08-16 fresh `validate:release` 输出为 103/103 公开页，全部有来源投影和正文依据标记；`executability-audit.json`（2026-08-15）为 103/103 页面、364 个 typed technical block、0 个未发布路径/隐含 cwd/untyped block。
4. **工程化学习材料不是装饰。** 16 个材料包以 canonical → public → static → ZIP 做 hash 闭包；技术块测试验证了 prompt 是否可复制、命令是否有公开 manifest 和 working directory、静态导出是否受 release gate 保护。
5. **AI 专项覆盖广且有边界意识。** 课程包含 RAG、评测、Agent、Serving、性能、质量平台、职业治理、Prompt/Eval/Mutation 等；引用层既记录“能证明什么”也记录“不能证明什么”，避免引用本身被误作验收证据。
6. **学习者结构好。** 统一的 outcome → 解释 → 例子/判断表 → action → expected result → common errors → completion check → evidence boundary，使小白能沿同一认知模型完成一条链路；这是可复用的教学设计资产。

## 5. 推荐的目标结构（可直接复用）

```text
业务目标与非目标
  → 风险登记与质量属性
  → Test Basis / 数据与环境版本
  → 测试策略与方法选择记录
  → 场景、负例、变异、Oracle 设计
  → 模型评测 + 系统集成 + 安全红队
  → 逐样本结果、统计不确定性、缺陷/风险处置
  → 发布门禁 / Waiver / 回滚
  → 线上监控、漂移、事故复盘、回归回灌
```

每一层都必须有：`输入版本`、`适用范围`、`风险`、`预期结果/容差`、`独立性`、`owner`、`运行收据`、`失败样本`、`退出或升级条件`。这将 ISO 过程思维、NIST TEVV 和大厂测试开发的证据闭环落到同一份可复制合同上。

| 4：发布判断 | release decision + monitoring plan | 仅消费已通过页面；复跑全链、审查外部版本变更、定义回滚与线上指标。 | 每项结论均有同代 hash 和 receipt；不存在“fixture → production”的越级声明。 |

## 7. 对用户的直接建议

1. 把这套课程当作**高质量的测试开发/AI 质量工程方法库与 fixture 练习平台**，而非“已验证的企业 AI 测试方案”。
2. 先做 P0-01～P0-04；它们修的是判断语言本身。若状态和统计不严谨，更多页面和更多样例只会放大误用。
3. 下一独立任务应严格沿项目 `validation` lane 执行，不修改/发布课程：真实模型 + 独立 Oracle + 从业者盲评 + 学员迁移任务。任何失败应转为最小 course/factory handoff。
4. 后续每个职业课程复用本报告的 0–4 量表和 TEVV 覆盖矩阵；五个硬门（过程、AI 特性、评估有效性、安全、工程证据）任一 ≤1，只能称“知识介绍”，不能称“专业可复用测试方案”。
